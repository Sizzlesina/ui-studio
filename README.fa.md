# UI Studio

اسکیل بازطراحی و ساخت رابط‌های متناسب با هر پروژه است. UI Studio ابتدا محصول و مخاطب را می‌شناسد، مرجع‌های مرتبط را بررسی می‌کند، سپس محدودهٔ توافق‌شده را طراحی یا بازطراحی و مستند می‌کند.

[English](README.md)

یک [پرامپت جامع فارسی](PROMPT.fa.md) هم برای استفاده بدون نصب اسکیل آماده است.

## نصب

نصب اسکیل منتشرشده از این مخزن:

```bash
npx skills add Sizzlesina/ui-studio --skill ui-studio
```

برای نصب سراسری:

```bash
npx skills add Sizzlesina/ui-studio --skill ui-studio -g
```

ابزار نصب امکان انتخاب ایجنت را می‌دهد. برای اجرای `npx` به Node.js و npm نیاز دارید؛ شرایط فعلی و گزینه‌های نصب در [مستندات رسمی CLI](https://github.com/vercel-labs/skills) آمده‌اند. خود این اسکیل وابستگی نرم‌افزاری یا اسکریپت نصب ندارد.

## استفاده

در ایجنت‌هایی که فراخوانی مستقیم اسکیل را پشتیبانی می‌کنند، از `$ui-studio` استفاده کنید؛ در بقیه، اسکیل را از رابط همان ابزار انتخاب کنید.

نمونه:

```text
$ui-studio
برای فروشگاه لوازم خودرو یک صفحهٔ اصلی کامل طراحی کن.
ابتدا موضوع، سبک، فونت، رنگ و هویت بصری را از من بپرس.
قبل از اجرا، اسکلت صفحه و پیش‌نمایش HTML دیزاین‌سیستم را نشان بده.
برای انتخاب عکس یا جایگزین آن هم از من سؤال کن.
```

نمونهٔ بازطراحی یک پروژهٔ موجود:

```text
$ui-studio
پروژهٔ فعلی من را بازطراحی کن. اول صفحات و مسیرهای اصلی را بررسی کن و ضعف‌های فعلی را با شواهد فهرست کن.
هدف، حفظ کارهای اصلی و هویت قابل‌استفاده است؛ ساختار و ظاهر را هرجا لازم است کامل و یکدست کن.
رقبای مرتبط و منابع معتبر تجربهٔ کاربری را بررسی کن، بعد مسیر طراحی را توضیح بده و صفحات داخل محدوده را کامل کن.
هیچ صفحه یا کامپوننتی را فقط با چند placeholder یا یک هیروی زیبا رها نکن. در پایان کل محدوده را در اندازهٔ دسکتاپ و موبایل بازبینی کن و گزارش بده چه چیزهایی حفظ، اصلاح، حذف یا اضافه شد.
```

نمونهٔ خروجی محدود:

```text
$ui-studio
برای سامانهٔ نوبت‌دهی کلینیک، فعلاً فقط ساختار صفحات و وایرفریم HTML بده.
طراحی نهایی و پیاده‌سازی را بعد از تأیید من ادامه بده.
```

## قابلیت‌ها

- شناخت موضوع، مخاطب و هدف پروژه با سؤال‌های کوتاه و مرحله‌ای
- توضیح سبک‌های طراحی و ساخت تصویر مفهومی در صورت درخواست و وجود ابزار
- دریافت یا پیشنهاد فونت، رنگ‌بندی و هویت بصری
- بررسی چند مرجع مرتبط و به‌روز با امکان مرور وب
- بررسی رقبا و منابع معتبر و تبدیل یافته‌ها به تصمیم‌های مشخص طراحی
- دو مسیر روشن برای ساخت تجربهٔ جدید و بازطراحی پروژهٔ موجود
- تکمیل همهٔ صفحات و اجزای داخل محدوده؛ جلوگیری از خروجیِ صرفاً نمایشی یا placeholderمحور
- بازبینی کل تجربه از نظر انسجام، تمایز، مسیرهای اصلی و رفتار در موبایل
- انتخاب روش استفاده از عکس یا جایگزین آن با نظر کاربر
- تحویل ساختار صفحات و وایرفریم HTML در صورت درخواست
- پیش‌نمایش HTML و تأیید دیزاین‌سیستم جدید قبل از اعمال آن، مگر با صرف‌نظر صریح کاربر
- تحلیل کلی، مشخصات طراحی، مستندات فنی و گزارش نهایی؛ تحلیل صفحه‌به‌صفحه در صورت درخواست

## روند کار

۱. **شناخت پروژه:** محصول، مخاطب، کارهای اصلی، محدوده، زبان، ترجیحات بصری، هویت موجود و انتخاب‌های مربوط به تصویر را مشخص می‌کند. پاسخ‌هایی را که قبلاً داده‌ای دوباره نمی‌پرسد.

۲. **تحقیق هدفمند:** در صورت دسترسی به وب، منابع معتبر UI/UX و رقبای واقعی را بررسی و مشاهده‌ها را به تصمیم طراحی تبدیل می‌کند؛ هویت رقبا را کپی نمی‌کند و از منابع تاریخ‌ندار ادعای «ترند روز» نمی‌سازد.

۳. **تعیین جهت طراحی:** شخصیت بصری، نقش رنگ‌ها، تایپوگرافی، تراکم صفحه، تصویر، ناوبری، رفتار تعاملی، واکنش‌گرایی، دسترس‌پذیری و حرکت را براساس نیاز پروژه مشخص می‌کند.

۴. **تکمیل محدوده:** بخش‌های معنادار و اجزای قابل‌مشاهده را با حالت‌های تعاملی لازم و چیدمان موبایل کامل می‌کند. در بازطراحی، تجربهٔ فعلی را بررسی و مسیرهای ضروری و هویت مفید را حفظ می‌کند.

۵. **بازبینی و مستندسازی:** در صورت مجاز بودن، کل صفحه را بررسی و ایرادهای مهم را اصلاح می‌کند؛ سپس کار انجام‌شده، فرض‌ها، موارد بررسی‌شده و محدودیت‌ها را گزارش می‌دهد.

### معیار کیفیت بصری

مینیمالیسم پیش‌فرض نیست؛ تراکم محتوا و شدت بصری باید با محصول، مخاطب و سبک انتخابی هماهنگ باشد. صفحهٔ کامل نباید مثل دمو یا بورد مفهومیِ خالی به‌نظر برسد. در عین حال، برای پُرکردن صفحه از متن بی‌هدف، تزئین اضافی یا ادعای تجاری ساختگی استفاده نمی‌شود. ریتم کل صفحه، کنتراست، پوشش نیازهای محتوا، کامل‌بودن اجزا و رفتار موبایل پیش از تحویل بازبینی می‌شود.

اگر اسکیل دیزاین‌سیستم جدیدی پیشنهاد کند، پیش از اعمال آن یک نمونهٔ HTML برای تأیید ارائه می‌دهد؛ مگر این‌که کاربر صریحاً این مرحله را واگذار کند. پیش‌نمایش صفحه و وایرفریم هم مرز تأیید جداگانه دارند؛ جزئیات در `SKILL.md` آمده است.

## فایل‌های همراه و ابزارها

فایل اصلی `SKILL.md` و پوشهٔ `references/` را با هم نگه دارید. راهنماهای لازم همراه اسکیل هستند. اسکیل‌های `ui-ux-pro-max`، `frontend-design`، `design-taste-frontend` و `anti-ui-slop` منابع تکمیلی اختیاری‌اند؛ نصبشان الزامی نیست و خودکار نصب نمی‌شوند.

مرور وب، تولید تصویر و اجرای پروژه به ابزارهای ایجنت میزبان بستگی دارند. این اسکیل محدودیت‌های کاربر دربارهٔ بیلد، سرور، مرورگر و کارهای پرهزینه را رعایت می‌کند. بررسی فایل‌ها به‌تنهایی تضمین کیفیت بصری یا عملکرد کامل نیست.

## انتشار در GitHub

۱. فایل `SKILL.md` را در ریشهٔ مخزن `Sizzlesina/ui-studio` نگه دارید و پوشهٔ `references/` را هم همراه آن منتشر کنید.

این دستور برای کاربرانی است که به مخزن عمومی GitHub دسترسی دارند. تغییر فایل محلی به‌تنهایی نسخهٔ GitHub را منتشر نمی‌کند. جزئیات فهرست‌شدن در skills.sh در [پرسش‌های رسمی](https://www.skills.sh/docs/faq) آمده است.
